# /human-copy — Editorial voice, not generated-sounding

Write or rewrite public prose (pages, articles, methodology, nav, forms)
so it sounds like a careful human. Generate if asked; never sound generated.

## Trigger phrases

`/human-copy`, `We need it to sound like it was written by a thoughtful human`, `we don't have any text that feels like it was generated by AI`, `It should be generated, but it should not sound generated.`

## Steps

0. Before editing files, follow [`../docs/wcp.md`](../docs/wcp.md) and skill `water-cooler-protocol`. Name yourself, write new files with no claim, and lease only a pre-existing file for the edit burst. Release before the next step. Do not push.
1. Inventory visitor-facing strings in the current repo (pages, articles, nav, CTAs, empty states, methodology). Skip admin-only chrome unless asked.
2. Read existing on-brand human copy in the same product and match that register.
3. Cut tells: stacked hedges, empty intensifiers, synonym piles, outline-shaped sections, and filler such as "delve", "leverage", "robust".
4. Prefer specific nouns and short sentences with one claim each. Keep this product's own glossary.
5. If the user asked for generated drafts, still write them in that voice. Do not add model disclaimers.
6. Show a short before/after for the worst offenders, then edit the files. Do not file an issue unless they asked.

## Do not

- Run a UI accessibility audit (that is `web-design-guidelines`).
- Restyle layout, color, or type (that is `design-ui` in the TanStack apps).
- Invent a brand-voice doc. Mirror copy already on the site.
